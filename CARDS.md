# Profile card maintenance

The **11 SVGs** in `cards/` are generated by `scripts/render_readme_cards.py` from
profile/project constants in that script, `data/contributions.json`, and committed
font assets in `fonts/`. Use Python 3.11+; collection and rendering use only the
standard library. No runtime pip install, font download, API key, or personal
access token (PAT) is needed.

## Card and link contract

In README order: `hero.svg`, `graph.svg`, `activity.svg`, `build.svg`, `learn.svg`,
`connect.svg`, `project-keyskills.svg`, `project-kairodash-devops.svg`,
`project-terraform-docker.svg`, `project-bun-cicd.svg`, and `stack.svg`.

- `graph.svg` is a separate **960 × 260** rolling-365-day calendar: exactly one
  12 × 12 cell per supplied date, a 16-pixel grid, month headers, and a footer
  legend. Leading/trailing space is not padded with invented dates.
- `activity.svg` is a **960 × 360** summary with contributions, active days,
  longest streak, busiest day, and monthly bars; it does not repeat the heatmap.
- Build/Learn/Connect tiles each use exactly `width="32.5%"`. The four featured
  repository cards are full-width, each wrapped in its real repository link:
  [KeySkills](https://github.com/NaveenGumaste/keyskills),
  [KairoDash DevOps](https://github.com/NaveenGumaste/kairodash-DevOps),
  [Terraform + Docker](https://github.com/NaveenGumaste/terraform-docker-03), and
  [Bun CI/CD](https://github.com/NaveenGumaste/cicd-project-01).
  Other website projects remain text links to portfolio/live pages; do not
  invent GitHub repository URLs for them.
- Website dark-mode neutrals are background `#0b0b0b`, card `#171717`, text
  `#fafafa`, primary `#e5e5e5`, muted surface `#262626`, and muted text `#a1a1a1`.
  Calendar levels are `#262626`, `#454545`, `#737373`, `#a3a3a3`, `#e5e5e5`.
  KeySkills alone uses its verified `#ff6b00` project accent; other featured
  repository accents and the global primary stay neutral.

## Embedded fonts and licensing

Each self-contained SVG embeds the pre-subset WOFF1 files as base64
`data:font/woff;base64,...` URLs in `@font-face` rules: **Hanken Grotesk 100–900**
(variable) and **Space Mono 400**. No external font request is made. Both assets
are licensed under **SIL Open Font License 1.1**; keep the two `fonts/OFL-*.txt`
licenses when redistributing them. These are real fonts, not system-font-only
approximations. Space Mono is a verified website UI family, not a claim that
all of the website's platform-dependent monospace text uses that face.

Normal rendering reads the committed, prebuilt subsets; it never runs
`pyftsubset`. For optional font rebuilding, pinned source URLs, FontTools setup,
exact `pyftsubset` commands, hashes, and coverage caveats, see
[fonts/README.md](./fonts/README.md) and [fonts/brand.json](./fonts/brand.json).
Only that maintenance step needs FontTools; daily automation does not.

## Regenerate and test

Render the committed calendar without network access (defaults: input
`data/contributions.json`, output `cards/`):

```sh
python3 scripts/render_readme_cards.py
```

Refresh real public data first; a failed fetch must not regenerate cached cards:

```sh
python3 scripts/fetch_contributions.py && python3 scripts/render_readme_cards.py
```

Create a static preview without changing committed cards:

```sh
python3 scripts/render_readme_cards.py --data data/contributions.json --output .preview/cards --static
```

`STATIC=1 python3 scripts/render_readme_cards.py --output .preview/cards` is
an equivalent static preview. `--data` and `--output` accept alternate paths.
For normal animated output, omit `--static` and leave `STATIC` unset. Static
output contains no keyframes, SMIL `animate*`, or `set` elements and presents the
final, motionless artwork. A leftover `animation-delay` alone is inert.

## Motion and reduced-motion fallback

CSS animates the `.card-enter` artwork wrapper and helper `.enter`, `.cell`,
`.bar`, `.pulse`, and `.orbit` elements. The artwork wrapper inherits timing from
the SVG root; only the fixed background frame sits outside it. Applying
`.card-enter` to the SVG root instead is equivalent. SVG root `--start` values
stage entrance in README order:
hero **0 s**, graph **0.5 s**, activity **1.35 s**, Build **2.2 s**, Learn **2.35 s**,
Connect **2.5 s**, repositories **3 + index × 0.22 s**, and stack **4.1 s**.
Helper delays add their offset with `calc(var(--start) + offset)`.

SMIL `animate` / `animateTransform` elements are allowed only below a
`.motion-layer`. Their final static counterparts live in `.still-layer` groups.
Under `prefers-reduced-motion: reduce`, CSS hides the motion layers, displays the
still layers, and forces all six animated CSS classes to `animation: none`,
`transform: none`, and `opacity: 1`. Disabling CSS animation alone would **not**
stop SMIL, which is why the separate layers matter. Scripts, event handlers,
`foreignObject`, and external resources are not part of the SVG contract.

Each README image loads independently; these delays are an intended visual
sequence, **not synchronized playback across SVGs**. Lazy loading, caching,
GitHub's image proxy, and browser SVG/font support can affect the presentation.
Use static output when a consumer cannot reliably display the animated version.

Run all tests offline (including README widths/links and embedded-font checks):

```sh
python3 -m unittest discover -s tests -v
```

## What the activity numbers mean

- The actual public calendar covers a rolling **365 days including today in
  UTC**, not a calendar year. Today's count is still in progress; committed
  cards describe the last successful fetch, not continuously live activity.
- Boundary months contain only dates inside that window, so their monthly
  totals may be partial. The streak statistic is the **longest streak within
  the window**, not the current streak or an all-time record.
- Collection reads GitHub's unauthenticated public calendar HTML. Markup,
  availability, or rate limits can change. Incomplete/ambiguous data fails
  rather than inventing counts; a failed collection preserves the existing
  JSON and prevents the workflow from rendering or publishing new cards.
- Public profile settings can expose anonymized private-contribution counts.
  Review those settings before publishing: the JSON records the username,
  date range, daily dates, counts, and levels, not repository names or details.
  These are publicly exposed calendar counts, not a complete activity audit.
- GitHub's image proxy/CDN may cache SVGs, so README images can lag behind a
  successful commit. Check the committed SVG and workflow run before retrying.

## Automation and permissions

`.github/workflows/refresh-cards.yml` refreshes daily at **04:23 UTC**, on manual
**Run workflow**, and on branch pushes changing the collector, renderer, tests,
`fonts/**`, `README.md`, `CARDS.md`, or the workflow. PR path filters cover the
same inputs. Scheduled runs use the **default branch** and may be delayed by
GitHub. GitHub disables scheduled workflows in public repositories after
**60 days of repository inactivity**; re-enable the workflow in Actions if needed.

PRs only run offline tests and render cached data into the runner's temporary
directory, outside tracked `cards/`. They do not fetch live data, persist checkout
credentials, or receive write permission. Refresh jobs test, fetch, render, then
stage only `cards/` and `data/contributions.json`; unchanged output makes no
commit. Per-branch concurrency serializes refreshes. Generated paths are excluded
from push triggers to avoid a bot loop. Pushes target the checked-out branch,
without assuming its name; manual refreshes must select a branch, not a tag.

Only the refresh job has `contents: write`. It uses the built-in `GITHUB_TOKEN`
through checkout for the bot commit/push, never for public calendar collection;
no PAT or custom secret is required. Enable Actions and allow read/write workflow
permissions under **Settings → Actions → General → Workflow permissions** if
restricted (organization policy may also apply). Branch protections/rulesets
must permit the Actions bot's direct push. The token cannot bypass push
restrictions: arrange a narrowly permitted automation path with the maintainer
rather than disabling protections or adding a PAT.

When forking, update `DEFAULT_USERNAME` in `scripts/fetch_contributions.py` and
profile/project constants in `scripts/render_readme_cards.py`, then re-fetch and
render. Changing names alone does not replace the original cached calendar.
`--username YOUR_GITHUB_USERNAME` overrides the collector for a one-off fetch;
set its default for future scheduled runs. Enable Actions/scheduling on the fork.
